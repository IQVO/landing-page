# ADR 0005: Executive briefing program pages under /briefings/

- **Status**: Accepted
- **Date**: 2026-11-11
- **Context**: Each repository ships a reveal.js executive briefing (committed at
  `executive/index.html`, generated by the executive pipeline). They were reachable only by
  knowing where to look. The landing page needed to present them the way the fleet presents
  everything: counted, cited, diagrammed.
- **Decision**: Add `/briefings/` — a hub plus one landing page per program: WMS/WES, retail
  network, yard management (YMS) and storefront, using the landing page's own template classes
  (`section`, `sec-head`, `engband`, `cta`, `caveat`). `scripts/collect-briefings.mjs` parses the
  committed decks' speaker notes (mission, capabilities, events, risks, next steps), assigns every
  registered context to a program (explicit members first, registry domains second), and writes
  `data/briefings.json`; `scripts/briefings.mjs` renders the pages inside `build.mjs`.
- **Parse contract (amended Nov 2026)**: v2 decks use action titles (full sentences), so the
  collector keys every slide on its `data-k` attribute (`cover`, `summary`, `mission`,
  `capabilities`, `domain`, `events`, `observability`, `footprint`, `roadmap`, `risks`,
  `architecture`) and falls back to the v1 fixed titles for older decks. It also reads the
  deck's big idea (`BIG IDEA:` in the summary notes) and hook (`HOOK:` in the cover notes); the
  big idea heads each briefed project. Deck links point at the hosted copies on the docs site
  (`/executive/<repo>/`), never at GitHub blob pages, which show HTML source.
- **Diagrams are data**: each program page draws its event-flow SVG from the context registry's
  real routes (solid arrows inside the program, crossing routes counted below); each briefed
  project draws its hexagon from the architecture assessment's counted adapters. No diagram is
  hand-drawn.
- **Honesty rules**: deck prose is quoted and credited; every figure is counted from
  engineering/architecture data; contexts without a deck appear under "not yet briefed" with the
  same counted chips; the registry's WES classification of the two network-bridge contexts is
  stated on the WMS/WES page instead of being silently reassigned.
- **Consequences**: `make briefings` refreshes the pages (fast: git + the day's two data files).
  `check.mjs` gates the five pages (banner, disclaimer, per-deck anchors, deck-count agreement,
  own size budget) and the landing page gains a § 09 band, a docs-list link and a footer link.
