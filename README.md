# landing-page

The public landing page for **IQVO** (Inventory + Queue + Value + Orchestration): a static site, served by nginx, that
explains the project as a Domain-Driven Design study and as an open experiment in AI agents, persistent memory and harness
engineering across different LLMs. It owns marketing copy, the IQVO visual presentation and a small set of numbers it counts
from the other repositories. It does **not** own any domain model, API or documentation content: the documentation lives in
[warehouse-docs](https://github.com/IQVO/warehouse-docs) and this page links to it.

## Disclaimer

This project is a domain-driven design study. It is not associated with, endorsed by or affiliated with any company, and it uses no company's code, data, logos or trademarks. All names, figures and examples are illustrative or synthetic.

## Architecture

No framework, no runtime dependency, no bundler. Node is used only for three small scripts; the shipped artifact is plain
HTML, CSS and JS plus self-hosted fonts.

```
src/                    what ships
  index.html            template: {{placeholders}} are filled from data/facts.json + site.config.json
  404.html
  assets/css/main.css   one stylesheet; tokens lifted from the IQVO logo
  assets/js/            boot.js (html.js flag), app.js (nav, reveal, tabs, bars), map.js, swap.js
  assets/fonts/         Bricolage Grotesque, Instrument Serif (italic), JetBrains Mono (SIL OFL, latin subset)
  assets/img/           iqvo-logo.png (transparent lockup), iqvo-mark.svg (vectorised mark)
data/facts.json         GENERATED by scripts/collect-facts.mjs, committed so builds work anywhere
data/engineering.json   GENERATED by scripts/collect-engineering.mjs (git + GitHub API), committed likewise
scripts/
  collect-facts.mjs     counts everything from the sibling repos; lays out the map deterministically
  collect-engineering.mjs  commits, PRs, CI runs, releases, lines and harness per repo, per ISO week and month
  engineering.mjs       renders the engineering study (overview, weekly reports, project studies) as static HTML + SVG
  build.mjs             src/ -> dist/, content-hashes css/js, inlines the map data, renders /engineering/
  check.mjs             the gate: links, ids, a11y basics, CSP, size budget, facts consistency
  serve.mjs             dev preview only
  smoke.sh              nginx image smoke test
deploy/                 nginx.conf (container), nginx-host.example.conf (host install), security-headers.conf
design/og-image.html    source of src/og-image.jpg
```

Rules the build enforces (`scripts/check.mjs`): no external resource is ever loaded; no inline `<script>` or `style=""`, so the
strict CSP in `deploy/security-headers.conf` holds; every link target exists; every image has `alt`; one `<h1>`; the domain
counts sum to the context count; the map has exactly as many nodes and routes as the facts say; size budget (HTML 90 KiB,
CSS 70 KiB, JS 50 KiB, fonts 200 KiB, total 700 KiB; the generated `/engineering/` pages have their own: 4 MB of HTML, 250 KB per page).
For the engineering study it also checks that every project and every week has its page, that per-project, per-month and per-week totals
add up to the fleet totals, and that each study page keeps the study-project banner and the verbatim disclaimer.

Accessibility: skip link, landmarks, visible focus, 44 px touch targets on coarse pointers, WCAG AA contrast on all text,
`prefers-reduced-motion` honoured (no pulses, no reveals, no stage animation), the map is operable by keyboard (arrow keys,
Home/End, Esc) and everything is readable with JavaScript disabled.

## Running it

```bash
make facts        # optional: recount from ../<repo> checkouts (reads origin/develop via git show)
make engineering  # optional: recount the engineering study (fetched ../ checkouts + GH_TOKEN or `gh auth`)
make check        # build + gate
make serve        # http://localhost:4173
make docker-test  # build the nginx image and smoke-test it read-only
make docker-run   # http://localhost:8080
```

| Setting | Where | Default | Effect |
|---|---|---|---|
| `SITE_URL` | env / `--build-arg` | `https://iqvo.cloud` (`site.config.json`) | Public origin, no trailing slash. Drives `canonical`, the Open Graph / Twitter tags, `sitemap.xml` and the `robots.txt` Sitemap line (all need absolute URLs). Empty in the config means those are omitted. |
| `DOCS_URL` | env / `--build-arg` | `https://iqvo.github.io/warehouse-docs` | Base of every documentation link. Point it at wherever the docs are served. |
| `docsUrl`, `githubUrl` | `site.config.json` | as above / `https://github.com/IQVO` | Same, for committed defaults. |
| `WS_ROOT` | env, `collect-facts` only | parent directory | Where the sibling repositories are checked out. |

## Deployment (nginx)

The page is public at **https://iqvo.cloud**, served by nginx. It is **not** published to GitHub Pages; CI verifies and publishes the image only.

Container (fleet-standard: `nginx-unprivileged`, uid 101, port 8080, digest-pinned bases shared with `ecosystem`):

```bash
docker build -t iqvo-landing-page --build-arg SITE_URL=https://iqvo.cloud .
docker run --rm -p 8080:8080 --read-only --tmpfs /tmp --tmpfs /var/cache/nginx --tmpfs /var/run iqvo-landing-page
```

Probes: `GET /healthz` returns `ok` (`Cache-Control: no-store`).

Host-installed nginx: `make build`, copy `dist/` to the web root and use `deploy/nginx-host.example.conf` plus
`deploy/security-headers.conf`. TLS and HSTS belong to the terminator and are deliberately not in these files.

Caching: css/js are content-hashed and served `immutable` for a year; fonts and images for 30 days; the HTML always
revalidates (`no-cache` + ETag), so a deploy is visible on the next request.

## Local development / quality gate

`make check` is the gate. Update the numbers with `make facts` (needs the sibling repositories fetched; it reads
`origin/develop`, never a working tree). `check.mjs` warns when `data/facts.json` is older than 45 days. Do not hand-edit
`data/facts.json` or any number in `src/index.html` that has a `{{placeholder}}`.

## Tests

`scripts/check.mjs` (offline, also run inside the Docker build) and `scripts/smoke.sh` (the built image). CI runs `make check`
then `make docker-test`. `node scripts/check.mjs --online` additionally HEADs every external link.
